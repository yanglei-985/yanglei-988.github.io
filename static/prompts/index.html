这些提示词是怎么写的

四条原则，来自《S31 对话深度解读》里的 GEPA、上下文工程和「形 · 法 · 神」

01 · 上下文先行

先告诉 AI 你是谁、为什么做

没有上下文，AI 只能按「平均用户」回答。所以几乎每张卡的开头都有一行【背景】和【目的】。

把这行背景一次写好，就是「上下文卡」；每次对话结束再把新信息沉淀回去。

S31 · theme 06 上下文工程
02 · 蒸馏「法」，不止「形」

写清楚怎么做，而不只是要什么

只给样例，AI 学到的是口吻和排版（形）；把高手的步骤和判断标准写出来，它学到的才是方法（法）。

每一步都带一句「做到什么程度算过关」。

S31 · theme 08 形 / 法 / 神
03 · 结构就是护栏

用固定的输出结构挡住幻觉

「不要遗漏」「不要编造」只能靠 AI 自觉；一张覆盖核对表、一栏「来源 + 时间」、一个「非原文请标明」，结果就能检查了。

这就是 Schema 与 Harness：护栏，而不是笼子。

S31 · theme 04 Schema / Harness
04 · 反思回流

交付前自检，交付后进化

每张卡结尾都有一步「交付前自检」，很多还会让 AI 说出「哪里不得不猜」。

用得不顺手，就把提示词和它的输出一起交给「提示词进化器」，进化出下一版。

S31 · GEPA 反思式提示词进化
进化循环：用一张卡 → 记下不满意的地方 → 连同输出交给 提示词进化器 → 新版本替换旧版本，改动写进「进化记录」。点开任何一张卡，底部都能看到它从 v1 到 v2 改了什么、为什么。
